# 👥 팀원 얼굴 인식 프로그램

팀원들의 사진으로 학습한 뒤, **단체사진에서 누가 누구인지 이름을 붙여 주는** 프로그램입니다.
얼굴로 사람을 구분하고, 그 사람의 **몸 전체 윤곽**을 색으로 표시합니다.
모든 처리는 **내 PC 안에서만** 이루어지며 사진이 외부로 전송되지 않습니다.

```
 [팀원 사진 등록] → [모델 학습] → [단체사진 인식] → (선택) [결과 바로잡기] → [성능 평가]
     1단계            2단계           3단계                 4단계                5단계
```

## 1. 한눈에 보기

### 무엇을 하나요?

| 입력 | 출력 |
|---|---|
| 팀원별 사진 20~30장 (라벨 = 이름) | 학습된 얼굴 인식 모델 |
| 처음 보는 단체사진 | 사람마다 **이름 + 점수** 표시, 몸 전체 윤곽 색칠 |
| 정답을 적어둔 단체사진 | 정확도, 혼동행렬, 임계값 그래프 |

### 전체 처리 흐름

```
사진
 │
 ├─[1] 얼굴 찾기 ─────────── SCRFD 검출기 (사전학습, 고정)
 │        얼굴 위치 + 눈·코·입 5점
 │
 ├─[2] 얼굴 정렬 ─────────── 5점을 기준으로 얼굴을 똑바로 펴서 112×112로 자름
 │
 ├─[3] 얼굴 특징 추출 ────── ArcFace ResNet-50 (사전학습, 고정)
 │        얼굴 → 512개의 숫자 (= "얼굴 지문", 임베딩)
 │
 ├─[4] 누구인지 판별 ─────── 둘 중 선택
 │        A. 최근접 이웃 (kNN)    : 팀원 사진들의 얼굴 지문과 비교 (학습할 가중치 없음)
 │        B. 분류 레이어 (MLP)    : 512 → 128 → 팀원 수, 우리가 직접 학습한 신경망
 │
 ├─[5] 외부인 걸러내기 ───── 팀원 사진과의 유사도가 임계값보다 낮으면 "모름"
 │
 └─[6] 몸 전체 윤곽 ──────── Mask R-CNN (사전학습, 고정)
          사람마다 몸 영역을 따서 [4]의 이름과 연결 → 색칠 + 테두리 + 이름표
```

> **핵심 아이디어 — 전이학습(Transfer Learning)**
> 수십만 명의 얼굴로 이미 학습된 신경망([1], [3], [6])은 그대로 쓰고,
> 우리 팀원을 구분하는 부분([4])만 우리 데이터로 학습합니다.
> 팀원 1명당 사진 20~30장처럼 데이터가 적을 때 가장 정확하고 안정적인 방법입니다.

## 2. 설치와 실행

### 실행 (이미 설치된 PC)

`run.bat`을 **더블클릭**하면 검은 창이 뜨고 몇 초 뒤 브라우저가 자동으로 열립니다.
(열리지 않으면 브라우저 주소창에 `http://127.0.0.1:7860` 입력)

- 프로그램을 쓰는 동안 **검은 창을 닫지 마세요.** 닫으면 프로그램이 꺼집니다.
- 검은 창이 이미 떠 있으면 `run.bat`을 또 실행하지 말고 브라우저만 새로고침(F5) 하세요.
  (두 번 실행하면 프로그램이 2개 떠서 헷갈립니다)

### 새 PC에 설치

필요한 것: Windows, Python 3.14, (권장) NVIDIA 그래픽카드

```powershell
git clone <저장소 주소>
cd <저장소 폴더>
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
# 몸 전체 윤곽(Mask R-CNN)용 PyTorch — NVIDIA GPU (CUDA 13)
venv\Scripts\python.exe -m pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cu130
# 설치 확인 (약 30초, 모두 ✅면 정상)
venv\Scripts\python.exe tests\test_all.py
```

- `dataset`, `eval`, `model`, `output` 폴더는 저장소에 없습니다(개인정보). 처음 실행하면 빈 폴더로 자동 생성되니, 1단계부터 사진을 등록하고 학습하세요.

- **처음 실행할 때** 사전학습 모델 파일을 자동으로 내려받습니다 (인터넷 필요, 1회만).
  - InsightFace `buffalo_l` (약 280MB) → `C:\Users\<사용자>\.insightface\models\buffalo_l\`
  - Mask R-CNN 가중치 (약 180MB) → `C:\Users\<사용자>\.cache\torch\hub\checkpoints\`
  - 모델 파일을 **받기만** 하며, 사진이나 데이터는 전송하지 않습니다.
- GPU가 없어도 동작합니다 (자동으로 CPU 사용, 더 느림).

### GPU / CPU

| 작업 | 장치 | 속도 (RTX 4060 Laptop 기준) |
|---|---|---|
| 얼굴 검출·특징 추출 | GPU (ONNX Runtime CUDA) | 사진 20장 학습 ≈ 2.4초 (CPU는 ≈ 32초) |
| 몸 윤곽 (Mask R-CNN) | GPU (PyTorch CUDA) | 단체사진 1장 인식 ≈ 0.3초 (얼굴 인식 포함) |
| 분류 레이어 학습 | CPU (numpy) | 1초 미만 (데이터가 작아 GPU가 오히려 느림) |

화면 맨 위 **상태 카드 4개**에서 현재 상황을 한눈에 볼 수 있습니다.

| 카드 | 내용 |
|---|---|
| 데이터셋 | 등록된 팀원 수·사진 수 (색 점 = 결과 이미지에서 그 사람의 색) |
| 학습 모델 | 검증 정확도(kNN·MLP), 학습 시각, 임계값. 학습 뒤 사진이 추가·삭제되면 **"⚠️ 데이터가 바뀜 → 다시 학습"** 경고 |
| 평가셋 | 정답을 지정해 저장한 단체사진 수·얼굴 수 |
| 연산 장치 | GPU(CUDA) / CPU 사용 여부 |

## 3. 사용 순서 (화면 1~5단계)

### 1단계 — 데이터셋 등록 (= 라벨링)

> 라벨링이란 사진에 정답을 붙이는 작업입니다. 이 프로그램에서는 **"이 사진들은 ○○○이다"** 라고 이름을 지정해 올리는 것이 곧 라벨링입니다.
> 사진은 `dataset\<이름>\` 폴더에 저장되고, **폴더 이름이 정답 라벨**이 됩니다.

1. **이름** 입력 (이미 등록된 사람에게 사진을 추가할 땐 **드롭다운에서 선택** — 한 글자라도 다르면 다른 사람으로 저장됨)
2. **팀원 사진** 칸에 사진을 끌어다 놓거나 클릭 후 `Ctrl+A`로 여러 장 선택
3. **등록** 클릭 → 결과 메시지 확인
   - ✅ 새로 등록 N장
   - ↩️ 중복이라 건너뜀 (이미 올린 사진)
   - ❌ 제외 (얼굴 없음 / 비슷한 크기 얼굴 여러 개 / 다른 사람으로 이미 등록됨 / 지원 안 되는 형식)
4. **"방금 등록된 얼굴" 갤러리 확인** — 잘린 얼굴이 모두 그 사람인지 봅니다.
   다른 사람이 섞였으면 아래 **"등록된 사진 관리"** 에서 그 사진을 클릭 → **선택한 사진 삭제**
5. 팀원마다 반복

### 2단계 — 모델 학습

1. **학습 시작** 클릭 (설정은 기본값 그대로 두면 됨)
2. 리포트 확인
   - 사람별 사용된 사진 수, **kNN 자기검증 정확도**
   - **분류 레이어 구조**와 **방식 비교표** (kNN vs MLP 검증 정확도)
   - **학습 곡선** 그래프
   - **헷갈린 사진** — 라벨이 틀렸거나 얼굴이 잘 안 보이는 사진일 가능성이 큼
3. **사진을 추가·삭제했다면 반드시 다시 학습**하세요. 모델은 자동으로 갱신되지 않습니다.

### 3단계 — 단체사진 인식

1. 단체사진을 올리고 **인식 방식**(kNN / MLP) 선택
2. **임계값**은 학습 때 자동으로 정해진 값 그대로 시작
3. **몸 전체 윤곽 표시** 체크(기본 켜짐) → **인식**
4. 결과: 사람마다 몸 전체가 색칠되고 **이름 + 점수**가 붙습니다. 결과 이미지는 `output\` 폴더에도 저장됩니다.
   - 모르는 사람에게 팀원 이름이 붙으면 → 임계값 **올리기**
   - 팀원이 "모름"으로 나오면 → 임계값 **내리기**

> 결과를 **보기만 하면 아무것도 저장되지 않습니다.** 평가용 사진을 여기서 미리 봐도 괜찮습니다.

### 4단계 — (선택) 결과 바로잡기 = 추가 라벨링

3단계에서 인식한 사진의 얼굴을 **학습 데이터로 추가**합니다.
셀카와 단체사진은 조명·각도·해상도가 달라서 단체사진 얼굴을 추가하면 단체사진 정확도가 올라갑니다.

- 틀린 얼굴: 얼굴 클릭 → 정답 이름 선택 → **선택한 얼굴을 이 이름으로 저장**
- 전부 맞음: **결과가 전부 맞음 → 모두 라벨로 저장** ("모름"은 저장 안 됨)
- 저장 후 **2단계에서 다시 학습**

> ⚠️ 여기서 저장한 사진은 학습 데이터가 되므로 **5단계 평가에 쓸 수 없습니다.**
> 단체사진이 적으면(8장 미만) 이 단계는 건너뛰고 **모두 평가용**으로 쓰세요.

### 5단계 — 성능 평가

**① 정답 단체사진 만들기** (학습에 쓰지 않은 사진만)

1. 사진 올리기 → **얼굴 검출** (이 화면에서만 얼굴 번호가 왼쪽부터 1, 2, 3… 으로 표시됨)
2. 얼굴 클릭 → 정답 선택 → **선택한 얼굴에 정답 지정** (자동으로 다음 얼굴로 이동)
   - 팀원 → 이름 / 팀원 아님 → **모름 (외부인)** / 너무 작거나 흐림 → **제외**
3. **평가셋에 저장** → 5~10장 반복

**② 평가 실행** → 두 방식의 정확도 비교표, 혼동행렬, 임계값 그래프, 틀린 얼굴 모음이 나옵니다.
팀원 사진을 바꿔 다시 학습한 뒤에도 **평가 실행만 다시 누르면** 됩니다 (정답은 저장되어 있음).

## 4. 사진 준비 가이드

### 용도별로 미리 나눠두기 (가장 중요)

```
내 사진 정리\
 ├─ 셀카_이름1\  (20~30장) → 1단계 데이터셋 등록
 ├─ 셀카_이름2\  …
 ├─ 단체_보강용\           → 3단계 인식 → 4단계 결과 바로잡기 (학습 데이터가 됨)
 └─ 단체_평가용\ (5~10장)  → 5단계 성능 평가 (학습에 절대 사용 금지)
```

**같은 사진을 학습과 평가에 동시에 쓰면** 이미 본 문제로 시험 보는 셈이라 점수가 부풀려집니다.

### 좋은 사진 조건

| 항목 | 권장 |
|---|---|
| 형식 | jpg, png, webp, bmp (**아이폰 HEIC 불가** → jpg로 변환. 설정 → 카메라 → 포맷 → "높은 호환성") |
| 구도 | **본인 얼굴이 가장 크게** (다른 사람이 같이 나와도 본인 얼굴이 2배 이상 크면 OK) |
| 다양성 | 정면·좌우 각도, 실내·실외 조명, 안경 착용/미착용, 가까이·조금 멀리 |
| 피할 것 | 강한 보정/필터, 마스크·선글라스, 연사로 찍은 거의 같은 사진 여러 장 |
| 크기 | 상관없음 (큰 사진은 자동 축소, 얼굴을 꽉 채운 근접 셀카도 처리됨) |
| 해상도 | 메신저로 압축된 사진보다 **휴대폰 원본**이 좋음 |

### 같은 사진을 다시 올리면?

| 상황 | 결과 |
|---|---|
| 같은 사람에게 같은 사진 다시 | ✅ 자동으로 건너뜀 (폴더째 다시 올려도 안전) |
| 같은 사람에게 새 사진 추가 | ✅ 누적 → 다시 학습 필요 |
| A로 등록된 사진을 B 이름으로 | ❌ 거부 + "이미 A로 등록됨" 경고 (라벨 실수 방지) |
| 4단계에서 같은 얼굴을 두 번 저장 | ✅ 건너뜀 |
| 4단계에서 잘못 저장 → 바른 이름으로 다시 저장 | ✅ 자동 정정 |
| 학습에 쓴 사진을 5단계 평가에 | ❌ 거부 |
| 평가셋 사진을 학습에 | ❌ 거부 |
| 같은 사진을 평가셋에 두 번 | ❌ 거부 |

> 중복 판정은 **파일 내용이 완전히 같을 때**만 됩니다. 카톡으로 다시 받았거나 잘라낸/크기를 바꾼 사진은 다른 파일로 인식되니, 원본을 용도별로 미리 나눠두세요.

## 5. 사용한 모델

| 역할 | 모델 | 무엇으로 학습됐나 | 크기 | 이 프로젝트에서 |
|---|---|---|---|---|
| 얼굴 찾기 | **SCRFD-10GF** (`det_10g.onnx`) | WIDER FACE 얼굴 검출 데이터 | 파라미터 420만 | 🔒 그대로 사용 |
| 얼굴 특징 추출 | **ArcFace ResNet-50** (`w600k_r50.onnx`) | WebFace600K (약 60만 명) | 파라미터 4,360만 | 🔒 그대로 사용 |
| 얼굴 윤곽점 | **2D 106점 랜드마크** (`2d106det.onnx`) | InsightFace 랜드마크 데이터 | 파라미터 130만 | 🔒 그대로 사용 (평가 화면 얼굴 표시용) |
| 몸 전체 윤곽 | **Mask R-CNN ResNet-50-FPN v2** (torchvision) | COCO (사람 포함 80종) | 파라미터 약 4,600만 | 🔒 그대로 사용 ("사람" 클래스만) |
| 팀원 구분 | **분류 레이어 MLP** (512→128→N) | **우리 팀원 사진** | 파라미터 약 6.6만 | ✏️ **직접 학습** |
| 팀원 구분 | **최근접 이웃 kNN** | **우리 팀원 사진** | 가중치 없음 (사진별 특징 저장) | ✏️ 사진 등록으로 구성 |

### ArcFace ResNet-50 내부 구조 (모델 파일을 직접 열어 확인한 값)

| 항목 | 값 |
|---|---|
| 입력 | 정렬된 얼굴 112×112 컬러 이미지 |
| 출력 | 512차원 벡터 |
| Conv 레이어 | 53개 (잔차 블록 24개 × 2 + 입력부 1 + 크기 맞춤 4) |
| BatchNorm / PReLU | 26 / 25 |
| 잔차 연결(Add) | 24개 = 3 + 4 + 14 + 3 블록 |
| 학습 방식 | **ArcFace 손실** (Additive Angular Margin Loss): 같은 사람은 벡터 방향이 가깝게, 다른 사람은 멀어지도록 각도에 여유(margin)를 두고 학습 |

> 공개 자료 기준 LFW 얼굴 검증 정확도 약 99.8%.

## 6. 학습은 어떻게 이루어지나

"2. 모델 학습"의 **학습 시작** 버튼을 누르면 아래 과정이 순서대로 실행됩니다. (코드: `face_core.py`의 `train()`)

### 6-1. 라벨 읽기
`dataset\` 아래 폴더 이름 = 사람 이름(라벨), 폴더 안 사진 = 그 사람의 학습 데이터.

### 6-2. 사진마다 얼굴 특징(512차원) 추출

1. **사진 읽기** — 휴대폰 회전 정보(EXIF)를 반영해 똑바로 세우고, 긴 변이 2400px보다 크면 축소
2. **얼굴 검출** (SCRFD, 입력 1024×1024)
   - 얼굴이 화면을 꽉 채운 **근접 셀카**는 검출기가 놓치기 쉬워서, 사진 둘레에 **회색 여백 25%** 를 넣은 버전으로도 검출해 합칩니다.
3. **주인공 얼굴 고르기** — 가장 큰 얼굴. 두 번째 얼굴이 가장 큰 얼굴의 50%보다 크면 "누가 주인공인지 모호"로 제외
4. **정렬** — 눈·코·입 5점을 표준 위치에 맞춰 112×112로 자름 (기울어진 얼굴도 똑바로)
5. **ArcFace** — 512개 숫자로 변환하고 길이를 1로 정규화 (→ 두 벡터의 내적 = 코사인 유사도)

추출 결과는 `model\emb_cache.pkl`에 저장해 두고, 다음 학습 때는 **새로 추가된 사진만** 계산합니다.

### 6-3. 방식 A — 최근접 이웃 (kNN)

- 학습할 가중치가 없습니다. 팀원별 512차원 벡터들을 **그대로 저장**합니다.
- 판별: 새 얼굴과 팀원 A의 모든 사진의 코사인 유사도를 구하고 **가장 비슷한 3장의 평균**을 A의 점수로 사용 → 점수가 가장 높은 사람 선택
  (1장만 보면 우연히 닮은 사진에 휘둘리고, 전체 평균은 각도가 다른 사진에 끌려 내려가서 3장 평균을 씀)
- **검증 — Leave-One-Out (LOO)**: 사진을 1장씩 빼고 나머지로 맞혀보기를 모든 사진에 반복 → "kNN 자기검증 정확도"

### 6-4. 방식 B — 분류 레이어 (MLP, 직접 학습)

**구조**

| 단계 | 레이어 | 출력 크기 | 파라미터 | 학습 |
|---|---|---|---|---|
| 백본 | ArcFace ResNet-50 | 512 | 4,360만 | 🔒 동결 |
| 입력 스케일 | × √512 (원소 분산 ≈ 1로 맞춰 학습 안정화) | 512 | - | - |
| 은닉층 | Linear 512→128 + ReLU + Dropout 0.3 | 128 | 65,664 | ✏️ |
| 출력층 | Linear 128→N + Softmax | N (팀원 수) | 129×N | ✏️ |

**학습 설정**

| 항목 | 값 | 이유 |
|---|---|---|
| 손실 함수 | 크로스엔트로피 (클래스 가중치) | 사람마다 사진 수가 달라도 공평하게 |
| 옵티마이저 | Adam, 학습률 0.001 | 작은 데이터에서 안정적 |
| 에폭 | 300 (전체 데이터를 한 번에 넣는 full-batch) | 데이터가 작아 미니배치 불필요 |
| L2 가중감쇠 | 0.001 | 과적합 방지 |
| 드롭아웃 | 0.3 | 과적합 방지 |
| 초기화 | He 초기화 (ReLU에 적합) | |
| 구현 | **numpy로 순전파·역전파를 직접 구현** | 계산 과정을 코드에서 모두 확인 가능 |

역전파(기울기 계산)는 수치 미분과 비교해 오차 10⁻⁸ 수준으로 정확함을 확인했습니다.

**데이터 분할 — train / validation**

```
팀원별 사진
 ├─ 80% → 학습용 (train)       ── MLP 학습
 └─ 20% → 검증용 (validation)  ── 학습에 쓰지 않고 매 에폭 정확도만 측정 → 학습 곡선
            (사람별로 20%씩 떼어냄 · 3장 미만인 사람은 전부 학습용)

같은 80/20 분할로 kNN도 채점 → 두 방식을 공정하게 비교 (방식 비교표)

검증이 끝나면 → 전체 100% 데이터로 다시 학습해 최종 모델로 저장
```

> 검증용 20%는 **성능을 측정하기 위한 용도**이고, 최종 모델은 데이터를 최대한 활용하려고 전체로 다시 학습합니다 (데이터가 적을 때의 일반적인 방법).
> 학습에 전혀 쓰지 않은 데이터로 하는 **진짜 시험(test)은 5단계 성능 평가**입니다.

### 6-5. "모름" 판정 임계값 정하기

1. LOO 과정에서 각 사진의 **본인 점수**와 **가장 높은 다른 팀원 점수**를 모읍니다.
2. 0.15~0.70 사이를 0.005 간격으로 바꿔가며 "본인은 통과 + 타인은 거부" 비율이 가장 높은 값을 찾습니다.
3. 똑같이 좋은 구간이 여러 개면 **구간의 가운데**를 고르고(여유 확보), 0.25~0.50 범위로 제한합니다.

### 6-6. 왜 ResNet-50 자체를 다시 학습하지 않았나?

- 팀원 4명 × 20~30장 ≈ 100여 장으로 4,360만 개 가중치를 학습하면 **과적합**(사진을 외워버림)이 일어나 단체사진에서 오히려 성능이 떨어집니다.
- 수십만 명으로 학습된 얼굴 특징 추출기를 그대로 쓰고, 그 위의 작은 분류기만 학습하는 것이 표준적인 방법입니다.
  (스마트폰 얼굴 잠금도 새 얼굴을 등록할 때 신경망을 다시 학습하지 않고 특징값만 저장합니다)

## 7. 단체사진 인식은 어떻게 이루어지나

(코드: `face_core.py`의 `recognize()`)

1. **얼굴 검출 + 특징 추출** — 6-2와 같음 (얼굴을 하나도 못 찾으면 여백을 넣어 재시도)
2. **점수 행렬** — 얼굴 × 팀원 점수표
   - kNN: Top-3 평균 코사인 유사도
   - MLP: 소프트맥스 확률
3. **이름 배정 — 헝가리안 알고리즘**
   한 사진에 같은 사람은 한 번만 나온다는 조건에서 **전체 점수 합이 최대**가 되도록 얼굴-이름을 짝짓습니다.
   (예: 두 얼굴이 모두 A와 가장 비슷해도, 더 비슷한 쪽만 A가 되고 다른 쪽은 차선의 이름이나 "모름")
4. **외부인 걸러내기** — 배정된 팀원과의 **kNN 유사도가 임계값보다 낮으면 "모름"** (두 방식 공통)
5. **몸 전체 윤곽 (Mask R-CNN)**
   - 사진 속 사람마다 픽셀 단위 몸 영역(마스크)을 땀 (신뢰도 0.6 이상)
   - 각 얼굴 박스가 어느 몸 영역 안에 얼마나 들어가는지(35% 이상) 계산 → 헝가리안 알고리즘으로 **몸 하나에 얼굴 하나** 연결
   - 몸이 안 보이거나 못 찾은 사람은 얼굴 윤곽만 표시
6. **표시** — 몸 영역을 사람별 색으로 반투명하게 칠하고 테두리, 이름표(이름 + 점수)는 **서로 겹치지 않는 자리**를 찾아 배치 (얼굴에서 떨어지면 연결선 표시)

> Mask R-CNN은 **윤곽 표시에만** 쓰이고 이름 판별에는 관여하지 않습니다. 따라서 평가 점수에 영향이 없습니다.

## 8. 화면의 숫자 읽는 법

### kNN 방식: 유사도 (예: `민수 0.68`)

코사인 유사도 = 두 얼굴 지문이 **얼마나 같은 방향을 가리키는지** (-1 ~ 1). **퍼센트나 확률이 아닙니다.**

| 값 | 의미 |
|---|---|
| 1.0 | 똑같은 사진 (다른 사진끼리는 사실상 안 나옴) |
| **0.4 ~ 0.8** | **같은 사람의 다른 사진**에서 보통 나오는 범위 |
| 0.0 ~ 0.3 | 다른 사람 |

- 셀카끼리보다 **단체사진은 낮게 나오는 것이 정상**입니다 (얼굴이 작고, 압축되고, 조명·각도가 다름).
- 중요한 것은 값의 크기보다 **정답 팀원 점수와 다른 사람 점수의 차이**입니다.

### MLP 방식: 확률 (예: `민수 97%`)

"팀원 N명 중 누구에 가장 가까운가"의 **상대적인** 확률입니다.
소프트맥스는 처음 보는 사람에게도 N명 중 누군가에게 높은 확률을 주기 때문에(닫힌 집합 분류의 한계),
**팀원이 맞는지는 결과 표의 "팀원 유사도" 칸**으로 판단하며, "모름"으로 판정된 얼굴은 유사도 값을 표시합니다 (예: `모름 0.21`).

## 9. 성능 평가 방법

(코드: `face_eval.py`)

1. **정답 매칭** — 평가 때 얼굴을 다시 검출하고, 저장된 정답 위치와 겹치는 정도(**IoU 0.4 이상**)로 짝지음
2. **채점 항목**

| 지표 | 의미 |
|---|---|
| 전체 정확도 | 모든 정답 얼굴 중 맞힌 비율 (외부인을 "모름"으로 처리한 것도 정답) |
| 팀원을 맞게 인식 | 팀원 얼굴 중 이름을 맞힌 비율 |
| 팀원을 다른 팀원으로 착각 | 가장 나쁜 오류 |
| 팀원인데 "모름" 처리 | 임계값이 너무 높으면 증가 |
| 외부인을 "모름"으로 처리 / 팀원으로 오인식 | 임계값이 너무 낮으면 오인식 증가 |
| 얼굴 검출 실패 | 너무 작거나 가려진 얼굴 |

3. **혼동행렬** — 행: 정답, 열: 예측. 대각선(굵은 숫자)이 맞힌 개수
4. **임계값 그래프** — 임계값을 바꾸면 정확도·외부인 오인식률이 어떻게 변하는지
5. **부정행위 방지 장치**
   - 평가 사진이 학습 데이터에 있으면 **데이터 누수 경고** (파일 해시로 확인, 4단계에서 저장한 단체사진 얼굴도 추적)
   - 평가셋을 보고 고른 "가장 좋은 임계값"은 점수를 부풀리므로 **보고서에는 학습 때 정한 임계값의 결과**를 쓰세요

> 평가 사진이 적으면 1개만 틀려도 수치가 크게 변합니다. 보고서에는 "93.3% (28/30)"처럼 **개수를 함께** 적으세요.

## 12. 한계와 주의사항

- **셀카 ↔ 단체사진 차이**: 단체사진은 얼굴이 작고(60~100px) 압축되어 유사도가 낮게 나옵니다. 다양한 셀카를 추가하거나 4단계로 단체사진 얼굴을 보강하면 개선됩니다.
- **연사 사진**: 몇 초 사이에 찍은 거의 같은 사진이 많으면 자기검증 정확도가 실제보다 높게 나옵니다.
- **평가 규모**: 평가 사진이 적으면 결과의 신뢰도가 낮습니다. 다른 날·다른 장소의 단체사진으로 늘리는 것이 좋습니다.
- **몸 윤곽**: 사진 밖으로 잘린 몸은 보이는 부분까지만, 여러 사람이 많이 겹치면 경계가 조금 섞일 수 있습니다.
- **쌍둥이·매우 닮은 사람**은 구분이 어려울 수 있습니다.
- **MLP 확률**은 외부인에게도 높게 나올 수 있으므로 "팀원 유사도"로 판단합니다 (8장 참고).

## 13. 자주 묻는 질문

**Q. 사진을 추가했는데 결과가 그대로예요.**
A. 2단계에서 **다시 학습**해야 반영됩니다.

**Q. 팀원이 "모름"으로 나와요.**
A. 3단계 임계값을 조금 내려보세요. 근본적으로는 그 팀원의 사진을 다양하게(각도·조명·거리) 추가하고 다시 학습하세요.

**Q. 등록 시 "얼굴 없음"으로 제외돼요.**
A. 얼굴이 가려졌거나 너무 흐리거나 어두운 사진입니다. 근접 셀카는 자동 처리되므로 대부분은 등록됩니다.

**Q. 등록 시 "비슷한 크기 얼굴 여러 개"로 제외돼요.**
A. 단체사진입니다. 단체사진은 3단계(인식) 또는 5단계(평가)에서 사용하세요.

**Q. kNN과 MLP 중 무엇을 써야 하나요?**
A. 5단계 평가 결과에서 정확도가 높은 쪽을 쓰세요. 데이터가 적을 때는 보통 비슷하거나 kNN이 약간 더 안정적입니다.

**Q. 검은 창이 바로 꺼져요.**
A. `venv` 폴더가 있는지 확인하세요. 오류 메시지가 창에 남도록 되어 있으니 그 내용을 확인하세요.

## 15. 테스트 방법

테스트는 두 종류입니다.

| 종류 | 무엇을 확인하나 | 방법 |
|---|---|---|
| **모델 성능 테스트** | 우리 팀원을 얼마나 잘 맞히는가 (정확도) | 화면 **5단계 성능 평가** (9장 참고) |
| **프로그램 기능 테스트** | 버튼·저장·차단 기능이 제대로 동작하는가 | `tests\test_all.py` (아래) |

### 프로그램 기능 테스트 실행

```powershell
venv\Scripts\python.exe tests\test_all.py
```

- 약 30초 걸리며(GPU 기준), 마지막에 `🎉 모든 테스트 통과`가 나오면 정상입니다. 실패가 있으면 종료 코드 1을 반환합니다.
- **실제 `dataset`·`model`·`eval` 폴더는 건드리지 않습니다.** 임시 폴더에서 실행하고 끝나면 지웁니다.
- 팀원 사진 없이 InsightFace에 들어 있는 **공개 샘플 단체사진(t1.jpg, 6명)** 으로 가짜 팀원 3명(가·나·다)의 셀카를 만들어 씁니다.
  (왼쪽 3명의 얼굴을 잘라 밝기·각도를 바꾼 사진 6장씩, 나머지 3명은 '외부인')
- 코드를 고친 뒤에는 이 테스트를 다시 돌려 기존 기능이 깨지지 않았는지 확인하세요.
